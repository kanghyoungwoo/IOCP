# 단위 테스트 (Google Test)

서버의 핵심 자료구조와 도메인 로직의 정확성을 검증하기 위해, Google Test 기반의 단위 테스트 163개를 구성했습니다. 단위 테스트는 네트워크나 DB 연동 없이 순수 C++ 로직만을 격리하여 검증하며, 카오스 엔지니어링(블랙박스 통합 테스트)과 상호 보완적인 역할을 수행합니다.

## 3계층 테스트 전략

```
Tier 1: 자료구조 단위 테스트     ← 격리된 순수 C++ 로직 (외부 의존성 없음)
Tier 2: 도메인 로직 단위 테스트   ← 패킷/User/Room 상태 머신 + Mock 기반 브로드캐스팅 검증
Tier 3: 시스템 통합 카오스 테스트  ← ChaosBotSystem (실제 TCP 소켓, 네트워크 고장 주입)
```

| 계층 | 도구 | 성격 | 검증 대상 |
|------|------|------|----------|
| **Tier 1** | Google Test | 화이트박스, 결정적 | RingBuffer, LockFreeStack, MPSCQueue, SPSCQueue, GlobalQueue_LockFree, ObjectPool |
| **Tier 2** | Google Test | 화이트박스, Mock 주입 | Packet 구조체, User 상태 머신, Room 입퇴장/브로드캐스팅 |
| **Tier 3** | [ChaosBotSystem](chaos-engineering.md) | 블랙박스, 확률적 | ABA 방어, Strand Race, 좀비 세션, 패킷 단편화 |

### Room 입퇴장 + 브로드캐스팅 Mock (18개) + EnqueueJob (10개)

```cpp
// Mock 주입 예시
room.SendPacketFunc = [this](UINT32 connIdx, UINT32 gen, UINT32 size, char* pData)
{
    sendCalls.push_back({connIdx, gen, size, {pData, pData + size}});
};
room.FreeJobFunc = [](PacketJob*) {};  // no-op (PacketJob 수명은 테스트가 직접 관리)
```

## 테스트로 발견된 버그

### ObjectPool::Free() — nullptr 체크 순서 오류

단위 테스트 작성 과정에서 `ObjectPool.h`의 잠재 버그를 발견했습니다.

**발견 경위**: `FreeNullptrSafe` 테스트 — `pool.Free(nullptr)` 호출 시 안전하게 무시되는지 검증하려 했으나, 테스트 실행 즉시 Assertion 발생:

```
Assertion failed: false && "ObjectPool::Free - pointer out of pool range"
```

**원인**: `Free()` 함수에서 **nullptr 체크가 범위 체크보다 아래에 위치**해 있었습니다.

```cpp
// 수정 전 — nullptr이 들어오면 범위 체크에서 먼저 발동
void Free(T* obj)
{
    if (obj < m_poolBlock || obj >= m_poolBlock + mPoolSize)  // nullptr(=0)이 여기서 true
    {
        assert(false && "ObjectPool::Free - pointer out of pool range");  // 발동!
        return;
    }
    ...
    if (obj == nullptr)  // 이미 늦음
        return;
}
```

`nullptr`의 주소값은 `0`이므로 `obj < m_poolBlock`이 `true`가 되어 assert가 먼저 터집니다.

**수정**: nullptr 체크를 함수 최상단으로 이동

```cpp
// 수정 후
void Free(T* obj)
{
    if (obj == nullptr)   // 가장 먼저 체크
        return;

    if (obj < m_poolBlock || obj >= m_poolBlock + mPoolSize)
    {
        assert(false && "ObjectPool::Free - pointer out of pool range");
        return;
    }
    ...
}
```

이 버그는 실제 서버 운용 중에는 `nullptr`을 `Free()`에 직접 넘기는 경로가 없어 발현되지 않았지만, 단위 테스트가 경계 케이스를 명시적으로 검증함으로써 잠재적 위험을 사전에 제거했습니다.
